# doit：角色與 subagent 分工

主 agent 在 Step2 決定分工，或依 SKILL.md Step6 的審查條件需要獨立審查時讀取本檔。何時需要審查由 SKILL.md 決定，本檔只說明怎麼做。

主 agent 負責到底，subagent 按需要分工。角色代表責任，不要求每次建立多個 agent。

## 角色

| 角色 | 責任 | 啟用時機 |
|---|---|---|
| 主 agent：規劃與整合 | 理解需求、規劃、實作、派工、維護進度檔、整合驗證、判定驗收與向使用者交付。 | 全程負責。 |
| 實作 subagent | 完成邊界清楚的子任務，驗證自己的修改，回報產出與阻礙。 | 有可獨立執行的子任務，分工能減少等待時。 |
| 審查 subagent | 對照使用者原話與實際修改，檢查需求遺漏、缺陷、回歸風險與驗證缺口，提供具體證據。 | 符合 SKILL.md Step6 的審查條件時。 |

## 啟用規則

- 依 SKILL.md「任務分級」決定分工深度：S 由主 agent 完成；M／L 在工作能明確切分且分工能減少等待時才平行實作，L 不強制分工。獨立審查另依 Step6 的風險與跨模組條件安排。
- 最多同時啟用 2 個 subagent，不含主 agent；平台可用數量較少時依其限制調整。平行的 agent 越多，主 agent 整合、處理檔案衝突與核對證據的成本越高；2 個已足以讓兩個獨立模組並行，或讓實作與審查分開。由主 agent 統一派工，subagent 不再自行建立下一層 agent，以免責任與進度紀錄分散。
- 使用當前環境提供的 subagent 能力。使用者呼叫 /doit 即已同意依本 skill 啟用 subagent；環境不提供時由主 agent 接手，並在交付中說明未做獨立審查。不把自我檢查稱為獨立審查。
- 審查優先交給未參與該部分實作的 subagent。

## 派工

每份派工交代：

- 目標，以及相關的使用者原話與驗收項目編號。
- 任務等級與風險，以及子任務適用的驗證與審查要求。
- 必要背景、相關介面與已確認的依賴產出。
- 可修改範圍與禁止的操作。
- 驗收方式、要執行的檢查，以及已知的原有失敗。
- 已知問題與剩餘嘗試次數。

同一份檔案同一時間只由一位實作者修改；共用介面由主 agent 先確認。無法切開的工作依序執行，需要擴大修改範圍時先回報主 agent 協調。

Subagent 不直接向使用者提問，將疑問與阻礙回報主 agent，由主 agent 統一提問。

## 回報與驗收

實作 subagent 回報時標示狀態：

| 狀態 | 意義 |
|---|---|
| 待審查 | 已完成並自我驗證，等待主 agent 核對。這是候選結果，不是驗收通過。 |
| 受阻 | 缺資訊、授權或依賴，無法繼續。 |
| 失敗 | 已嘗試但未達成目標。 |
| 已取消 | 依主 agent 通知停止。 |

回報內容包含：完成事項、實際修改的檔案、執行的檢查與實際結果、未解決問題、需要的決策，以及每次處理嘗試。

主 agent 核對實際修改與證據後，才更新進度檔與驗收狀態；不只依賴 subagent 的完成聲明。主 agent 是進度檔的唯一寫入者；主 agent 交接時，先確認舊主 agent 已停止寫入，再接手同一份檔案。

## 審查發現

審查 subagent 讀取使用者原話、驗收項目、實際 diff 與驗證證據，不以任務摘要或實作者結論代替。審查以讀取、檢查與回報為主，不直接修改受審程式。

每項發現包含：編號、依據（對應的驗收項目或風險）、位置或重現方式、影響、嚴重度，以及如何驗證修正。

- **阻擋性**：導致驗收項目無法通過，或造成缺陷、資料或安全風險。必須修正並重新驗證，才能宣告完成。
- **非阻擋性**：改善建議或風格偏好，記入審查紀錄，不阻擋交付。

主 agent 確認發現後安排修正；修正後由審查者或另一位未參與該修改的 subagent 確認關閉。主 agent 判定某項發現無效時，在審查紀錄寫明理由；屬於需求取捨的爭議交由使用者決定。同一阻擋性發現的修正次數適用 SKILL.md 的 3 次上限。

## 異常與變更

- **同一問題只有一位處理者**：每次嘗試後回報結果，由主 agent 更新計數再安排下一次，避免平行重試超過上限。
- **Timeout 或失聯**：先確認該 subagent 已停止寫入，並保存它已產出的修改與紀錄，再將同一範圍改派他人。無法確認已停止前，該範圍維持由它占用。
- **遲到或重複的回報**：以主 agent 最新派工為準；針對舊派工或舊需求的回報只保留紀錄，不覆蓋較新的結果，也不重複整合。
- **需求、介面或任務狀態改變**：主 agent 通知受影響的 subagent，並將受影響的驗證結果改為未驗證。
- **任務停止或取消**：停止派工，通知並停止仍在執行的 subagent，保留已產出的工作。
- **最終整合**：主 agent 收齊必要產出、確認 subagent 不再修改檔案後，才進行最終整合驗證與歸檔。
