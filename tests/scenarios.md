# doit 流程情境檢查

修改流程規則後，以本表逐項核對 `SKILL.md`、`references/progress.md` 與 `references/subagents.md`。這是文件規則的人工推演，不代表 Claude Code／Codex 宿主實測通過。

## 檢查方式

1. 只依每列的情境及上述三份規則，寫下任務等級、模板、審查需求或下一步；不適用的欄位略過。
2. 對照預期判定；規則缺漏、互相矛盾或允許錯誤路徑時判定失敗，不以自行補充的假設算通過。
3. 記錄實際判定與依據，覆寫「最新推演紀錄」；歷次紀錄由 git 歷史保存。規則改動後重跑受影響的情境；宿主實測另記錄宿主、版本、操作與輸出，未執行就保持未驗證。

## 情境與預期判定

除另有說明，假設工作可在一次對話完成、未要求平行實作，且環境可安排未參與實作的審查者。

| 編號 | 情境 | 預期判定 |
|---|---|---|
| C1 | 只把頁尾版權年份改為 2026，不改變行為。 | S、精簡模板、主 agent 檢查；不強制新增測試或獨立審查。 |
| C2 | 修正單一模組的權限檢查，影響與依賴明確，主 agent 實作。 | M、精簡模板加審查紀錄；取得修正前失敗證據並驗證修正，由未參與實作的人獨立審查。 |
| C3 | 新增功能需同步調整前端與後端模組，工作無法獨立切分。 | L、完整模板、記錄依賴與整合順序；可由主 agent 依序實作，仍須整合驗證與獨立審查。 |
| C4 | 接續舊五步驟進度檔：目前是 Step4 Verify，實作完成、驗證未執行。 | 核對工作區後進入新 Step5 Verify，補判等級；不將舊 Step4 當成新 Step4 Execute，也不改寫歷史紀錄。 |
| C5 | 同一問題第三次驗證成功，記錄已解決；下一次對話還有其他工作。 | 核對現況後可接續其餘工作，保留三次紀錄，不因次數為 3 而重新要求授權。 |
| C6 | 同一問題第三次驗證仍失敗，使用者尚未明確要求繼續處理該問題。 | 停止本次任務及仍在執行的 subagent，保留進度檔並通知使用者；不得自行開始第四次或重設計數。 |
| C7 | 本次驗收全部通過；審查發現另一個模組的舊缺陷，未被本次修改惡化且不影響本次驗收。 | 非阻擋性；記入審查紀錄及交付限制，不自行擴大修正範圍，其他完成條件成立時可交付完成。 |
| C8 | 舊缺陷阻止本次驗收通過，但修正超出已授權範圍。 | 阻擋性；請使用者決定擴大範圍，繼續可獨立完成的工作；解決前不可宣告完成或歸檔為已完成。 |
| C9 | 本次修改讓原有資料外洩問題更嚴重，即使原驗收項目未涵蓋它。 | 阻擋性，不能以「原有問題」排除；須解決並重新驗證才能完成。 |
| C10 | Subagent A 實作受審部分；A 自評通過，B 未參與實作且可用。 | 派 B 獨立審查；A 的自評不能替代獨立審查，B 不接手該部分修正。 |
| C11 | 高風險修改需審查，但環境不提供 subagent。 | 主 agent 自我檢查，記錄原因並註明「未做獨立審查」；仍須滿足驗收與阻擋性發現的完成條件。 |
| C12 | 審查者 B 發現問題後直接參與修正，另有未參與該部分的 C 可用。 | B 不再符合獨立審查條件，改由 C 確認受審部分及修正，不以 B 的確認當成獨立關閉。 |
| C13 | M 任務使用精簡模板，由 Step2 進入 Step4，沒有須立即補記的事件；Step4 完成後無預警中斷。 | Step2 進入 Step4 不必寫檔；Step4 完成時已寫入修改的檔案與「待驗證」；接續時依此核對工作區，再進行 Step5。 |
| C14 | 修正單一模組的一般 bug，不涉及其他高風險類別，依 Step4 新增回歸測試。 | M；新增測試不屬於弱化測試保障，不強制獨立審查；仍須取得修正前的失敗證據。 |
| C15 | 為了讓失敗的測試通過，修改既有測試的斷言或加上 skip。 | 屬於弱化測試保障；依驗證判準先取得使用者決定，執行時需要獨立審查。 |
| C16 | 規劃模式交付後標示「等待使用者」；使用者在新對話以 /doit 確認計畫並要求實作。 | 判定為接續，沿用同一份進度檔；確認結果記入「計畫變更」，回 Step1 將驗收項目改寫為實作的成功條件。 |
| C17 | 沒有參數呼叫 /doit，`.doit/` 根目錄只有一份未歸檔進度檔。 | 直接沿用該檔，核對工作區後從記錄的下一步繼續；不詢問使用者選擇。 |
| C18 | 兩個 subagent A、B 都參與了受審部分實作，修改涉及高風險類別。 | 實作完成並結束其中一個後，另啟用未參與的新 subagent 審查；同時不超過 2 個 subagent，A、B 都不得擔任審查者。 |
